# Переезд сайта: бэкап и смена домена

Составлено 09.09.2026, когда аккаунт GitHub попал под ограничение
торгового контроля США. Публичные репозитории и Pages сохранены,
приватные отключены — сайт работает, но зависеть от одного аккаунта
не стоит.

## 1. Что уже сохранено

`~/claude-projects/personal/BACKUP-SITE/w2w-site-ГГГГММДД.bundle` —
**вся история репозитория одним файлом** (`git bundle --all`,
проверен `git bundle verify`). Из него сайт восстанавливается целиком:

    git clone w2w-site-20260909.bundle site
    cd site && git remote set-url origin <новый адрес>

Обновлять бэкап после заметных правок:

    cd site && git bundle create ../BACKUP-SITE/w2w-site-$(date +%Y%m%d).bundle --all

Копию класть на Яндекс.Диск — локальный диск тоже не вечен.

## 2. Чего нет в репозитории и что придётся завести заново

| Что | Где взять |
|---|---|
| `TG_TOKEN` | у @BotFather, бот уже создан |
| `TG_CHAT` | @userinfobot, это число |
| `YD_PUBLIC` | публичная ссылка на папку наблюдателя на Яндекс.Диске |

Секреты GitHub не выгружаются даже владельцем — только перезаписываются.

## 3. 🔴 Купить домен стоит ДО того, как он понадобится

Если привязать свой домен к нынешнему репозиторию, пока всё работает,
GitHub сам начнёт перенаправлять `w2w-portfolio.github.io` на него —
**поисковая история и ссылки переедут без потерь**. Если же сначала
потерять доступ, а потом покупать домен, перенаправлять будет нечему:
накопленная индексация останется на мёртвом адресе.

Порядок: купить домен → в настройках Pages вписать его в Custom domain →
у регистратора прописать записи, которые покажет GitHub → дождаться
галочки HTTPS. После этого хостинг можно менять когда угодно: адрес
сайта больше не зависит от того, чей он.

## 4. Что править при смене адреса

Домен зашит ровно в пяти местах:

| Файл | Что |
|---|---|
| `bin/i18n_build.py:42` | `HOST = 'https://w2w-portfolio.github.io'` — отсюда идут canonical, hreflang, карта сайта, robots |
| `tpl/_head.html:17` | `og:image` — абсолютный адрес картинки для карточек ссылок |
| `i18n/ru.json`, `en.json`, `es.json` | по одному текстовому упоминанию в каждом |

После правки — `python3 bin/i18n_build.py`, затем `bin/site_lint.py`
и `bin/audit_page.py`: оба должны быть зелёными.

## 5. Что нужно сделать снаружи

* **Поисковики** — новый адрес это новый ресурс: подтверждать заново
  в Яндекс.Вебмастере и Google Search Console, заново отправлять карту.
  Файлы подтверждения нынешнего адреса (`yandex_*.html`, `google*.html`)
  останутся в репозитории, они не мешают.
* **Яндекс.Метрика** — счётчик `112331649` привязан к домену
  в настройках; добавить новый адрес, иначе статистика оборвётся.
* **Ссылки на площадках** — профиль MQL5 (два места: контакты и «Обо мне»,
  на каждом языке отдельно), витрина Tickmill, Myfxbook, описание канала.
* **Телеграм-канал** — старые посты со ссылками не переписать, поэтому
  перенаправление с `github.io` важнее, чем кажется.

## 6. Если GitHub всё-таки закроется

Сайт статический: любой хостинг статики поднимет его из бэкапа за
полчаса. Что понадобится помимо файлов — переписать сборку публикации
(сейчас это Pages из ветки `main`) и перенести еженедельный отчёт
`.github/workflows/weekly.yml` на то, что будет вместо Actions:
он ходит за отчётами наблюдателя на Яндекс.Диск и пересобирает страницы.
