# Тревоги в Телеграм — где живут и как проверить

Сторож **работает на VDS, рядом с терминалом**, а не в облаке:
`!FOREX_VDS/w2w_setup/w2w_guard.ps1` на Яндекс.Диске. Запускается через
`w2w_guard.bat` из автозагрузки, смотрит сводку наблюдателя раз в
**15 минут** и пишет, только когда состояние изменилось.

## О чём приходит сообщение

* 🔕 наблюдатель молчит дольше **двух часов** — терминал упал или встала
  запись; ✅ когда данные снова пошли;
* 🟡🔴 сменился уровень риска (норма / внимание / разбор / стоп) —
  уровень считает сам `TC_Watch` и кладёт в `w2w_status.json`, сторож
  только сравнивает с прошлым;
* 📊 закрылись новые сделки — короткой сводкой, а не по одной.

Повторов нет: прошлое состояние лежит в `w2w_guard_state.json`.

## Как проверить, что сторож жив

Оба файла рядом со скриптом на Яндекс.Диске, то есть видны и с мака:

    tail -5 ~/Yandex.Disk.localized/!FOREX_VDS/w2w_setup/w2w_guard.log

Строки вида «без событий: снимок …, уровень норма, сделок 2» — норма:
значит он смотрит и молчит по делу. В `w2w_guard_state.json` — то же
состояние в виде json (кодировка UTF-8 **с BOM**, читать
`encoding='utf-8-sig'`, иначе `json.load` падает).

Токен бота и адрес чата лежат в `w2w_guard.cfg` рядом со скриптом,
двумя строками `TOKEN=` и `CHAT=`. В переписку их не вставлять.

## Запасной путь — вручную с мака

`bin/tg_watch.py` остался как запасной и для разовых проверок. Доступы
берёт из переменных окружения:

    TG_TOKEN=… TG_CHAT=… python3 bin/tg_watch.py --test   проверить связь
    TG_TOKEN=… TG_CHAT=… python3 bin/tg_watch.py --dry    показать, не отправляя

## Почему не в облаке (решение 04.09.2026)

Задание `pulse.yml` в GitHub Actions **удалено** (коммит `b742149`):
расписание просыпалось через раз — за ночь три запуска из девяти — и
проспало закрытие сделки на два часа. На VDS сторож рядом с терминалом
и от чужого расписания не зависит.

В облаке осталось только `weekly.yml` — еженедельный отчёт по субботам
в 09:00 UTC. Для ленты недель задержка расписания роли не играет.

⚠️ **Секреты репозитория `TG_TOKEN` и `TG_CHAT` остались с тех времён
и больше ничем не используются** — `weekly.yml` их не читает. Удалить
их можно безболезненно; пока лежат, это просто лишние ключи в чужом
хранилище.

## Если бота придётся заводить заново

1. @BotFather → `/newbot` → имя любое, username оканчивается на `bot`.
2. Ответом придёт токен вида `8123456789:AAF3k…` — это пароль от бота.
3. Открыть `t.me/<имя_бота>` и нажать «Запустить»: бот не может написать
   первым.
4. Узнать свой chat_id: @userinfobot ответит `Id: 123456789`.
5. Вписать обе строки в `w2w_guard.cfg` на VDS.
